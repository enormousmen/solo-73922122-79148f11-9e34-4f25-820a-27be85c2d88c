# 单卷恢复控制台(volume-recovery)

虚拟机数据盘尚未恢复完,值班员需要立刻恢复业务读写。本服务提供单卷恢复页:

- **4 KiB 块读写**:本地块用 SQLite 持久化(`<DATA_DIR>/volume.db`);本地缺块时从**内置只读备份镜像**读透;
- **后台回填**:网页一键启动,后台线程把缺块从备份拷贝到本地,页面实时显示进度;
- **按块挂起/放行**:网页可挂起指定块的后台备份读取;挂起期间同一块的**整块写入照常提交**,
  迟到的备份数据(`INSERT OR IGNORE` + 落盘前复查挂起表)**不会覆盖**已提交的业务写入;
- **重启续传**:已落盘的块保存在 SQLite 中,进程重启后保留,且未完成的回填**自动继续**;
- **试写(一次一轮)**:恢复页可开启一轮试写。试写期间**所有整块写入都只记入试写区**
  (`trial_blocks`,每轮每块最多一份额外副本,重复试写覆盖),**读块优先返回本轮最近一次试写内容**;
  后台回填只补原卷,**只有试写数据的块仍算缺块**,原卷补齐前**拒绝断开备份**。
  **提交**在单个事务内把试写一次性并入原卷;**放弃**只删试写改动,期间回填到原卷的数据保留;
  提交/放弃任一步失败则整体回滚,**原卷与本轮试写都保持原状**;试写轮次持久化,**重启后可继续**;
  **试写进行中拒绝重置卷**;
- **断开保护**:只要还有缺块就**拒绝断开备份**(HTTP 409);补齐后允许断开,断开后数据盘纯本地读写。

## 目录结构

```
app/
  app.py               # Flask 服务:存储层(Volume)+ 回填 worker + REST API + 页面
  backup_util.py       # 只读备份镜像生成器(内容确定性,可由块号推导)
  templates/index.html # 单页控制台:状态卡、块网格、块操作、一键演示脚本
  requirements.txt     # flask
  Dockerfile           # 构建期生成 /app/backup.img 并 chmod 0444(内置只读镜像)
tests/
  test_recovery.py     # pytest 自测(18 项,含试写 11 项)
docker-compose.yml     # 一键启动:8080 -> 5000,命名卷 recovery-data 持久化 /data
```

## 运行

### Docker Compose(交付方式)

```bash
docker compose up --build
# 打开 http://localhost:8080
```

- 容器内 `/app/backup.img` 为构建期生成的只读备份镜像(256 块 × 4 KiB = 1 MiB);
- 本地块存于命名卷 `recovery-data` 中的 SQLite,`docker compose restart` 后保留并自动续传。

### 本地直跑(开发/自测)

```bash
pip install -r app/requirements.txt
python3 app/app.py          # http://localhost:5000
```

可用环境变量:`BLOCK_SIZE`(默认 4096)、`BLOCK_COUNT`(默认 256)、`BACKFILL_DELAY`(默认 0.05s/块)、
`DATA_DIR`、`BACKUP_IMAGE`、`PORT`。

## 网页演示

页面顶部为状态卡与进度条;中部为 16×16 块网格(灰=原卷缺失,绿=本地·回填,蓝=本地·业务写入,
紫=试写未并入,深紫=原卷·试写提交,黄=已挂起),点击块可读取/整块写入/挂起/放行;
控制区可**开始试写 / 提交试写 / 放弃试写**;底部为**一键演示脚本**,依次执行并打印日志:

1. 重置卷 → 2. 开始试写 → 3. 向**缺块** 7 整块写入(只记试写)→ 4. 读块 7 返回试写内容 →
5. 挂起块 7 的原卷回填并启动回填 → 6. 其余块补齐后缺块仍为 1(试写不算补齐)→
7. 仅试写数据的缺块时断开备份被拒(409)→ 重复开始试写被拒 → 试写期间重置被拒 →
8. 放行块 7 → 9. **原卷补齐** → 10. 读块 7 仍是试写内容 → 11. 断开备份成功 →
12. **放弃试写**(只丢试写,回填保留)→ 13. 读回块 7 的**备份数据**。

**重启持久化演示**:回填进行中执行 `docker compose restart`,刷新页面可见已落盘块保留、
回填自动继续(`GET /api/status` 的 `resumed_on_boot=true`);若重启时试写轮次未结束,
刷新后仍是同一轮次,可继续写入、提交或放弃。

## API 一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/status` | 总块数/已落盘/缺失/进度/回填与备份状态/试写轮次/统计 |
| GET | `/api/blocks` | 已落盘块及来源、挂起列表、试写轮次与试写块 |
| GET | `/api/block/<i>` | 读块:试写命中 / 本地命中 / 缺块读透备份 / 挂起 409 / 断开且缺失 410 |
| POST | `/api/block/<i>/write` | 整块写入(`{"data": "..."}`,UTF-8 ≤ 4096 B,补 0 凑整块);试写期间写入试写区(响应 `written: "trial"`) |
| POST | `/api/block/<i>/suspend` · `/resume` | 挂起 / 放行该块的后台备份读取 |
| POST | `/api/backfill/start` | 启动后台回填(已断开备份则 409) |
| POST | `/api/disconnect` | 断开备份:有缺块则 409 拒绝,补齐后断开成功 |
| POST | `/api/trial/start` | 开启一轮试写(已有进行中的轮次则 409) |
| POST | `/api/trial/commit` | 单事务把本轮试写并入原卷;失败整体回滚并返回 409 |
| POST | `/api/trial/abort` | 单事务丢弃本轮试写(保留期间回填);失败整体回滚并返回 409 |
| GET | `/api/trial` | 当前试写轮次信息 |
| POST | `/api/reset` | 清空本地卷(演示用);试写进行中返回 409 |

## 关键设计

- **迟到备份数据不覆盖业务写入**:回填落盘用 `INSERT OR IGNORE`;从备份取数到落盘之间的窗口内
  若业务写入已提交,回填结果被丢弃(统计 `late_ignored`);落盘前还会复查挂起表,取数后被挂起的块直接丢弃。
- **挂起语义**:挂起只影响*后台*备份读取——回填 worker 跳过被挂起的块;缺块且被挂起时业务读返回 409;
  整块写入不受挂起影响,永远可提交。
- **持久化**:块、挂起表、回填运行标志、断开标志、试写轮次与试写块全部在 SQLite(WAL);重启后按标志自动续传,
  未结束的试写轮次原样保留。
- **断开条件**:`missing > 0` 时断开返回 409;`missing` 只按**原卷** `blocks` 计算,试写区的数据不计入,
  因此"只有试写数据的块"仍是缺块。断开后关闭备份 fd,读写在纯本地完成。
- **试写隔离**:试写块存在 `trial_blocks(round_id, idx, data)`,与 `blocks` 完全分离——
  所以提交/放弃只需要动这一张表;`PRIMARY KEY(round_id, idx)` 保证每块只有一份额外副本(重复试写覆盖)。
  `trial_round` 上有部分唯一索引 `WHERE state='open'`,数据库层面保证同一时刻最多一轮。
- **提交/放弃的原子性**:`_finish_trial_locked` 内"并入原卷(逐块 UPSERT)→ 删试写副本 → 轮次置为
  committed/aborted"共用一个事务,任一步抛错都 `rollback()`,原卷与本轮试写都保持调用前状态;
  接口返回 409 并提示"未改变"。回滚后本轮仍是 open,可重试提交/放弃。
- **读取优先级**:本轮试写命中 > 原卷 `blocks` > 备份读透(受挂起/断开限制);试写期间后台回填照常补原卷,
  但不会覆盖或删除试写副本。

## 自测情况(已执行)

- **pytest 18 项全部通过**(`python3 -m pytest tests/ -v`,Python 3.11 + Flask 3.1):原有 7 项
  (缺块读透且不落盘、回填至完成、挂起期间读拒/写可提交/放行后业务数据不被覆盖、缺块拒绝断开+补齐后断开+
  断开后可读写、跨重启保留块并自动续传、写入校验、回填并发业务写入不被覆盖)+ 试写 11 项:
  只开一轮(含数据库唯一索引兜底)、试写写入隔离且读回试写、每块只保留一份试写副本、
  仅试写数据时拒绝断开、原卷补齐后可断开、提交并入原卷、放弃只丢试写并保留回填、
  提交失败整体回滚(注入触发器在半途报错)、放弃失败保持原状、试写期间拒绝重置、跨重启继续试写。
- **真实 HTTP 冒烟**(独立进程 + curl):重置 → 开始试写 → 向缺块 7 试写 → 读回试写 →
  重复开始 409 → 缺块时断开 409 → 回填 64 块 → 原卷补齐后断开 200 → 放弃试写 →
  读回块 7 的备份数据(`BACKUP-BLOCK-000007|…`)→ 重置恢复可用,全部符合预期。
- **页面演示脚本实跑**:用最小 DOM 垫片在 Node 里直接执行 `index.html` 的演示函数,对真实服务跑完 13 步,
  日志全部为 `✔`(见上方"网页演示");页面脚本另做了语法与 DOM id 引用检查。
- **真实跨进程重启**:用 `timeout`/自退出包装进程启动两个独立进程先后接管同一 `DATA_DIR`;
  第二轮次进程启动后 `/api/status` 显示同一 open 轮次、读块 5 仍是重启前的试写内容、
  重复开始与重置均 409、断开备份 200、提交后读回原卷来源 `trial`。
- **compose 配置**:本环境无 Docker,未实际构建镜像;已用 PyYAML 校验 `docker-compose.yml` 语法与关键字段,
  并在本地实测了 Dockerfile 中的镜像生成命令(`backup_util.py`,产物 1 MiB 且内容可复现)。

## 已知限制 / 未完成

- **未实际构建/运行 Docker 镜像**(环境无 Docker,且沙箱内进程无法接收信号);Dockerfile 与 compose
  只经静态校验和命令级实测,**镜像内首跑与 `docker compose` 全流程未在真实 Docker 上验证**。
- 试写轮次是**卷级**的:一轮开启后,该卷的**所有**整块写入都记为试写,没有"仅对某些块试写"的白名单。
- 试写提交按块 UPSERT,**不校验**试写期间该块的原卷是否被外部改动(单实例内不会发生,多实例共享
  SQLite 文件时以最后一次提交为准);也没有试写内容的版本号/冲突检测。
- 提交/放弃失败靠 SQLite 事务回滚保证;但若进程在 `commit()` 执行途中被强制杀死,恢复能力取决于 WAL 自身,
  未额外实现崩溃恢复流程或试写日志重放。
- 使用 Flask 内置开发服务器(单进程多线程),非生产级 WSGI;块网格规模按 256 块设计,超大卷未做分页。
- 无认证鉴权,`/api/reset` 可清空卷,仅限内网演示;统计计数器在内存中,重启后归零(块数据/试写本身持久)。
- 备份镜像为本地文件;"断开备份"为逻辑断开(关 fd + 标志位),未模拟网络卷卸载。
- 挂起期间业务读缺块返回 409(不读备份),未实现"读等待回填"或"挂起仅挡后台、读透放行"等其它策略;
  试写期间挂起语义不变(挂起只挡后台回填/读透,不挡试写读取与试写写入)。
